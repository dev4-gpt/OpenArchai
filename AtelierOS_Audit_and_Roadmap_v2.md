## 3. Before adding anything new: verify what's real vs. templated

Given how much of this audit turned up a "real API call with a canned/template fallback" pattern, the highest-leverage next step is a one-day audit, not a new feature:

1. **Check which path `agents-orchestrator.ts` actually takes in the deployed app.** If `generateContextualFallback`'s keyword-matched hardcoded responses are what users see (rather than a live Gemini/LLM call), the "AI Studio Team" is currently a scripted demo, not an agent system — impressive-looking but not defensible as "AI" in front of a technical client or investor.
2. **Set `HIGGSFIELD_API_KEY` and confirm real video generation actually runs end-to-end**, or explicitly gate the walkthrough feature as "coming soon" until it does. Shipping a feature that silently plays a stock mixkit.com video when the key is absent is a reputational risk the moment anyone inspects network traffic.
3. **Decide whether `services/video/walkthrough_generator.py` and the Blender bake script are dead code or the intended production path** — right now you have three different, non-unified attempts at "video walkthrough" (in-browser Three.js capture, headless Blender, Higgsfield API) and none of them is clearly *the* one. Pick one as primary, keep at most one fallback, delete the rest — this alone will materially reduce the pipeline's surface area for bugs.

## 4. Concretely aligned upgrades, by pipeline stage

### 4.1 Rendering & multi-view consistency (the one real README gap left)
- **Swap SDXL→FLUX for the render stage.** [FLUX.1 schnell is Apache-2.0](https://huggingface.co/black-forest-labs/FLUX.1-schnell) (fully commercial, no gotchas) and benchmarks ahead of SDXL on photorealism and prompt adherence; FLUX.1-dev is higher quality but is non-commercial without a paid BFL license — use `schnell` for the free/open path, keep SDXL as the license-safe fallback ([FLUX vs SDXL comparison](https://pxz.ai/blog/flux-vs-sdxl), [FLUX licensing guide](https://artificialguy.com/blog/flux-licensing-commercial-use/)).
- **Close the multi-view gap with the tool you already wrap.** MeltFlex's `/api/v1/world` endpoint (Gaussian splat, `.spz` output, hosted viewer, already in `packages/architect-skills/meltflex/meltflex-3d/SKILL.md`) is the fastest path to a genuinely walkable, multi-view-consistent output — call it from the main render pipeline instead of only from a Claude-skill context. This also retires the need to build or maintain your own splatting/NeRF stack.
- **If you want a self-hosted splat pipeline instead of the MeltFlex dependency**, [`gsplat`](https://github.com/nerfstudio-project/gsplat) (Apache-2.0, CUDA-accelerated, maintained by the Nerfstudio team) is the standard permissively-licensed library; pair with [Nerfstudio](https://docs.nerf.studio/nerfology/methods/splat.html) (also Apache-2.0) if you want the full training pipeline rather than just the rasterizer.

### 4.2 Reconstruction & scale calibration
- **Automate the door-width heuristic you already documented as a TODO** in `reconstruct.py` — you already run door/window segmentation (`floorplan_model`), so detecting a door polygon's width and assuming ~0.9m (already your DXF pipeline's own default clear-width assumption) gets you automatic calibration for the raster path without a UI change, closing the last gap between `reconstruct.py` and the already-accurate `reconstruct_cad.py`.
- **`RoomFormer` (CVPR 2023)** — [single-stage transformer floorplan reconstruction](https://github.com/ywyue/RoomFormer) is worth evaluating as a segmentation upgrade path over the current UNet+ResNet34; confirm its license terms before adopting (not confirmed permissive in this pass — check the repo's `LICENSE` file directly before use, unlike the already-verified MIT `Yytsi/floorplan-to-3d` weights you're using now).
- Your **IFC export gap** (doors/windows/slab/rooms have no 3D shape, only schema placement) is a bigger practical blocker than any new model — a BlenderBIM-based headless geometry pass (you already depend on Blender for the walkthrough bake) could generate the missing `IfcExtrudedAreaSolid` shapes in the same container.

### 4.3 MCP / agentic tooling
- Your own `openarchai_server.py` MCP server is already a strong asset — the highest-value addition isn't a new MCP server, it's **wiring your existing skills/MCP tools to actually call each other** (e.g., `generate_walkthrough_reel` calling the real Higgsfield endpoint instead of building an unused spec, `meltflex_ai_restyle` actually executing instead of returning a "ready_for_execution" payload).
- For Blender-side tooling, [BlenderMCP](https://blendermcp.org/setup/claude) or the [Blender MCP marketplace listing](https://www.claudemarketplace.net/mcp/blender-mcp) would let an agent drive your existing `blender_walkthrough_bake.py` scene interactively rather than as a one-shot CLI script.
- For BIM/IFC, [`freecad-mcp`](https://github.com/sandraschi/freecad-mcp) (46+ tools across BIM/CFD/FEM) or [`ODA MCP servers`](https://www.opendesign.com/cn/products/mcp-servers) (STEP/IFC/DWG core, commercial) are worth evaluating if you want an agent to inspect/edit IFC files beyond what `build_ifc.py` generates programmatically.

### 4.4 Infrastructure (Modal alternatives / free tiers)
- Modal's current free-tier-plus-pay-per-second model remains reasonable for your current bursty GPU load (segmentation + SDXL/FLUX inference); the main reasons to look elsewhere would be cost at scale or cold-start latency for the render step specifically.
- **fal.ai** offers per-output pricing for exactly the model types you run (SD/FLUX/depth-ControlNet) with no idle cost, but its free tier is minimal (~$1 credit, "more demo than usable") — best evaluated as a per-image-cost alternative to A10G-hour billing once you have real usage data ([fal.ai pricing](https://aitoolsatlas.ai/tools/fal-ai/pricing)).
- **RunPod has no free tier as of Sept 2026** ([confirmed](https://costbench.com/software/ai-gpu-cloud/runpod/free-plan/)) but has the cheapest per-second community-cloud rates if you outgrow Modal's pricing — a cost-optimization move, not a free-tier one.
- **Baseten** gives new workspaces **$30 in free credits** for both serverless model APIs and dedicated GPU deployments — closest thing to a genuinely usable free trial among the Modal alternatives surveyed ([Baseten free tier](https://pricepertoken.com/endpoints/baseten/free)).
- **Google Colab's free T4 tier** (dynamic ~15-30 GPU-hrs/week, 12h session cap) is fine for offline experimentation/training runs (e.g., fine-tuning the segmentation model) but not for a production inference endpoint ([Colab 2026 guide](https://joshthompson.co.uk/ai/google-colab-2026-guide-free-compute-automations-pro-tips/)).

### 4.5 Google ecosystem
- **Google Flow** (Veo-3.1-based AI filmmaking tool, [official announcement](https://blog.google/innovation-and-ai/products/google-flow-veo-ai-filmmaking-tool/)) is a legitimate alternative or complement to the Higgsfield walkthrough path — it's a consumer-facing creative tool (storyboard/keyframe workflow) rather than a raw API as of this check, so it's better suited to producing a one-off marketing/launch video (like the GTM doc's 90-second cinematic script) than to a per-project automated pipeline call. For the latter, Google's own video-gen API path is **Veo on Vertex AI**.
- **Vertex AI's $300/90-day new-customer credit** covers Imagen (image) and Veo (video, private/limited preview per region) — worth using for a side-by-side quality comparison against your FLUX/SDXL render stage and the Higgsfield/MeltFlex video paths before committing spend to any one vendor ([Vertex AI free trial](https://cloud.google.com/vertex-ai)).
- **Gemini API free tier has tightened materially in 2026** — Pro-series models were removed from the free tier in April 2026 and now require billing; only Flash-tier models remain genuinely free, and *any* billing enablement on a project removes free-tier access entirely, even for calls that would've qualified ([Gemini free tier changes](https://help.apiyi.com/en/google-gemini-api-free-tier-changes-april-2026-guide-en.html)). Your existing `apps/web/src/lib/gemini.ts` (voice intent parsing, likely also backing the agent consult) should be budgeted assuming Flash-only free usage, not Pro.

### 4.6 Cost estimation
- Your BOQ engine (5 line-item categories, area-multiplier based) is a reasonable "client-facing ballpark" tool but thinner than dedicated products like BoqCalc/CUBE/bidyou.ai, which do real takeoff from drawings and query live supplier pricing. Given you already parse real wall/door/window elements in `reconstruct_cad.py`, the natural upgrade is per-element (not per-area) quantity takeoff — actual linear meters of each wall type, actual door/window counts by size — feeding the same rate tables for a materially more defensible number.
